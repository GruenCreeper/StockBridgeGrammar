# StockBridgeGrammar 1.0.0 使用说明

插件用于 Rhino 8 / Grasshopper：把曲线识别为「节点 + 杆件」图，匹配材料库存，应用形状语法，再输出几何。插件提供 **15 个组件、19 条规则**。节点保留三维坐标；识别过程不推断上下弦、斜竖杆角色或节间，支座由用户指定。

## 1. 安装

安装包中，本指南旁边已附有 `StockBridgeGrammar.gha`，可直接安装，无需编译。关闭 Rhino，把该文件复制到 `%APPDATA%\Grasshopper\Libraries\`；如文件属性中有“解除锁定”，先解除，再重启 Rhino 8。只保留一份已安装插件。组件位于 **StockBridge** 标签页。

只有使用源码包或仓库代码时才需要编译：使用支持 .NET Framework 4.8 目标框架的 .NET SDK，在 `StockBridgeGrammar.csproj` 所在目录执行 `dotnet build -c Release`，再按上述步骤安装生成的 `bin/Release/StockBridgeGrammar.gha`。

可按下表手动连线，或使用[示例目录](examples/README.md)中的 Python 脚本生成画布。

## 2. 基本连线

| 输出 | 输入 |
| --- | --- |
| Curve 参数 | Recognize.C |
| Recognize.J | Assign.G |
| Example Stock.J 或 Stock Inventory Builder.J | **Assign.S 和 Apply.S** |
| Assign.G | Apply.G、Target Picker.G |
| Assign.M | Target Picker.M |
| Target Picker.T | Apply.T（使用 ID 的规则） |
| 一个 Rule ID 文本 | Apply.R、Rule Params Builder.R |
| Rule Params Builder.P | Apply.P |
| Apply.G | Decode.G |

选杆件用 Target Picker 的 `by_curve`，C 接一根曲线；选已有节点用 `by_point`，Pt 接一个点，T 返回最近节点 ID。Tp 输出独立传递输入点的原始坐标。

Mo 留空时，自动优先级为非空 Id → 有效 Target Curve（C）→ 有效 Target Point（Pt）→ 不匹配排序。Id 选当前图中的杆件或已有节点；C 选杆件；Pt 选最近的已有节点，并从 Tp 透传原始坐标。三个输入都没有时才按不匹配排序；不匹配也为空则选第一根杆件。Id 填写后若找不到，将报错并停止，不会自动改用 C/Pt。若 Mo 明确连接了其他模式，该模式优先；显式固定不匹配排序可将 `by_mismatch_rank` 接到 Mo。

按 ID 选择时，接当前 Graph 到 Picker.G，再把 `M1` 或 `N2` 等 Panel 接到 Picker.Id，Mo 留空。Picker.T 输出 ID，Picker.S 给出匹配摘要，Graph Label 可显示实际 M/N ID；结构变更后要传入更新图。按 ID 选已有目标与指定新点坐标是两件事，后者用 Picker.Tp → Apply.Tp。

每一步查看 Apply 的 H（规则记录）和 W（拒绝或诊断信息）。连续改写时，把前一步的 Updated Graph 接到下一步 Apply.G。库存单位必须与坐标一致；例子按米编写，不应把毫米模型坐标直接与米制库存混用。

## 3. addNodeToStock：三个锚点与一个期望位置

**Position 决定连接哪三个点，Target Point 决定希望新节点靠近哪里。**

1. Apply.R 填 `addNodeToStock`，连接完整 Graph 和 Stock。
2. 在 **Position (Pt)** 接恰好三个互异、不共线的锚点。三个点应在同一个列表分支中。也可以在参数中提供 `points:[[x,y,z],…]`，或 `corners:["N0","N1","N2"]` 指定已有节点。
3. 在独立的 **Target Point (Tp)** 接一个期望的新节点位置。可以直接接 Rhino Point，也可以接 **Target Picker.Tp**。
4. 明确提供锚点时，Apply.T 可以留空。Params 可留空，或填 `{"minHeight":0.01}`。

算法以三个锚点为球心、三根可用实物库存的**原长**为半径，寻找三个球的交点，并选择距 Tp 最近的可行空间解。新节点固定连接三根杆，每根杆对应一根未重复占用的实物料，长度等于那根料的原长。

新点到锚点平面的距离必须达到 `minHeight`，默认 **0.01 米**。库存不足、锚点退化或原长组合没有满足高度要求的空间交点时，规则会拒绝；不会退回共面点，也不会截短材料凑出一个点。`degree` 固定为 3。

同一组三球通常可能有上下镜像解：把 Tp 放在平面上方或下方，会选择更接近期望位置的可行解。Tp 是选择条件，**不保证输出点与 Tp 重合**，因为位置还受库存原长约束。需要明确方向时请始终连接 Tp。

[空间加点验证例子](examples/add_node_spatial/README.md) 使用三根 2 米料；锚点 `(0,0,0)`、`(2,0,0)`、`(0,2,0)` 时，上下解分别为 `(1,1,±√2)`。例子包含 Graph、Stock 和上下目标的 Params JSON，便于直接复查长度和离面高度。

`addConnectionPoint` 是另一条按锚点形心布置 hub 的规则；它与此处的三球交会原长加点不是同一算法。

## 5. 19 条规则速查

| Rule ID | 目标与用途 | 常用参数 |
| --- | --- | --- |
| `splitMemberByStockLength` | member；按库存切分，尝试给切点补连支撑 | `maxBridgesPerNode` |
| `addConnectionPoint` | member；利用附近锚点形心添加 hub | `extraAnchors` |
| `removeConnectionPoint` | degree-2 node；删节点并合并两杆 | `{}` |
| `triangulateBay` | member；在已有节点之间补一条三角边 | `{}` |
| `densifyWithShortStock` | member；按短库存细分并尝试补连 | `{}` |
| `fanOutLoadPath` | member；从端点向附近已有节点补连 | `fanCount` |
| `removeRedundantMember` | member；满足端点度数守卫时删杆 | `{}` |
| `shiftNodeToMatchStock` | node 或 member；移动节点改善库存适配 | `{}` |
| `articulateChainToStock` | split-chain 前缀或子杆；利用余长折链 | `foldDown` |
| `connectNodeToStock` | node 或 split-chain；添加可达支撑连接 | `maxConnectionsPerNode` |
| `mergeSplitChain` | split-chain 前缀或子杆；恢复原始杆件 | `{}` |
| `addNodeToStock` | 三个锚点 + Tp；用三根原长库存生成离面节点 | `minHeight`，默认 0.01 |
| `removeNode` | node；删除非支座节点及关联杆件 | `{}` |
| `dissolveNodeToDiagonal` | hub node 或汇交杆；消去 hub、补一条边 | `pairBy` |
| `crossBracePanel` | 两条侧边；转为中心节点与交叉支撑 | `sides` |
| `uncrossPanel` | X 中心节点或辐条；恢复两条侧边 | `{}` |
| `dedupeMembers` | `*` / `all` 或 node；清理重复及零长杆 | `removeZeroLength` |
| `splitEdgeToPoint` | member + 连接点；折分原边并补连 | `to`，以及 Pt/Fp 输入 |
| `relocateMember` | member + 两个新端点；移动杆件 | Pt 输入或目标 ID 列表 |

完整参数例子见 [rule_params_examples.json](examples/rule_params_examples.json)。每条规则都有适用条件，拒绝某个目标不等于插件故障。

Rule Params Builder 的 **Extra Params JSON (X)** 可在默认参数上覆盖当前有效参数。设 **Use Defaults (Def)=false** 时 X 和 Fan Count 生效；Def=true 时忽略这两者。Fan Count 仅用于 fanOutLoadPath。

标记为 deprecated 的参数仅保留用于画布兼容，不参与规则控制。使用 Rule Library 列出的参数。

## 6. Section Check 与候选方案

Section Check 使用提供的轴力与库存属性进行逐杆检查。Stress Limit（SL）和 Buckling Limit（BL）分别控制应力与屈曲比限值，默认均为 1.0；输出比值不因限值而改变。详见[截面检查阈值](examples/section_check_limits.md)。

检查后执行**一个**建议修改，使用 **Section Check.G2 → Apply.G，Nr → Apply.R，Nt → Apply.T**，Stock 继续接 Apply.S。G2 带有检查写回的库存分配；Ru/T 是逐杆报告列表，不应拿来代替单步 Nr/Nt。被建议的规则仍可能需要用户补充锚点或目标点。

形状变化后，应针对更新后的结构重新求轴力，再继续检查；直接环接 GH 连线不构成迭代求解器。Section Check 的 `noForce` 表示该杆没有提供轴力，不等于通过受力验算。

Generate Candidates 的每个候选位于独立分支。将 G 输出直接接 Candidate Selector.CG，它会读取整棵候选树；再用索引选择，名称和规则记录以输出为准。

Design Drama 与 Grammar Intensity 共同缩放规则尝试次数；Max Iterations=0 时保留基础几何。Include Lean Reuse (A) 控制是否加入该候选家族，不代表保证结构镜像对称。

## 7. 示例、常见问题与范围

[示例索引](examples/README.md)提供基本配线、画布生成脚本、库存文件及已知坐标的空间加点例子。[自定义库存说明](examples/custom_stock_merge.md)介绍多分支库存输入和数量核对。

- **换 Target Point 没影响：**检查是否连接了 Tp 输出到 Apply.Tp；T 只含 ID。也可能不同期望点仍以同一个可行库存解为最近点。
- **addNodeToStock 无结果：**检查三个锚点是否互异、不共线，库存数量是否够，长度是否能组成满足 `minHeight` 的三球空间交点。先运行随附 2 米料验证例子。
- **Apply 未改变图：**查看 W；核对规则 ID、目标类型和必需输入，尤其是 Stock.S。
- **画布连线与说明不对应：**用随附脚本生成新画布，或按本说明中的参数名检查连线。
- **节点/杆件数量或标签不清楚：**读取 Recognize.Report，或使用 Graph Label 查看 ID。

插件执行几何约束、库存分配和部分拓扑诊断；提供轴力时可做逐杆检查。节点/杆件计数和度数守卫**不是整体结构稳定性证明**，警告也不一定阻止图输出。需要查看每一步记录，并对改写后的结构另行分析。
